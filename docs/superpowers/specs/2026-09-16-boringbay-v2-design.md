# BoringBay V2: 渐进式产品升级设计

**状态：** 待用户复核  
**日期：** 2026-09-16  
**仓库：** `cantoblanco/boringbay`

## 1. 背景

无聊湾当前是一个以独立博客成员列表为核心的站点联盟。现有 Rust/Axum 应用提供成员展示、UV/RV 统计、等级、30 天排行、总排行、即将移除列表、实时访客通知、加入说明，以及 Badge、Icon、Favicon 和 WebSocket 接口。

V2 的目标不是重写或替换现有产品，而是在保留品牌、功能、数据和接口的前提下，提高功能价值、趣味性、成员导流和自然传播能力。

## 2. 已确认的产品决定

1. 产品定位保持为“独立博客圈升级版”，不发展为重型社交社区。
2. 同时追求三类结果：访客回访、成员博客导流、更多博主加入和分享。
3. 首版不要求登录；个人进度保存在浏览器本地。
4. RSS/Atom 采用成员自愿提供 Feed 的方式，不自动抓取未明确提交的内容源。
5. 保留当前主要功能和设计语言，允许现代化排版、响应式布局、动效和卡片细节。
6. 排行榜和“即将移除”功能保留，但允许重新设计规则与表达。

## 3. 目标与非目标

### 3.1 目标

- 保留无聊脸 SVG、红/粉色、昼夜模式和轻松幽默的品牌气质。
- 保留全部历史成员与统计数据，不要求成员更换现有嵌入代码。
- 让新访客在 10 秒内找到明确的探索入口。
- 让曝光较少的新站和小站获得公平的发现机会。
- 通过每日航线、护照、漂流瓶和分享卡形成可持续的探索循环。
- 让排行和成员状态规则透明、可解释、可申诉。
- 在不保存长期个人身份的情况下获得必要的聚合产品指标。

### 3.2 非目标

- 不建设账号、关注、私信、评论或用户动态系统。
- 不托管成员博客正文。
- 不把无聊湾改造成通用 RSS 阅读器。
- 不自动删除成员。
- 不在首版引入 React、Vue 等重型前端框架。
- 不在功能开发中顺带重写整个后端。

## 4. 向后兼容约束

以下内容是 V2 的硬性兼容边界：

- `/`、`/rank`、`/join-us` 保持可访问。
- `/api/badge/:domain`、`/api/icon/:domain`、`/api/favicon/:domain` 和 `/api/ws` 保持兼容。
- 现有 Badge、Icon、Favicon 的视觉语义和统计行为不发生破坏性变化。
- `resources/membership.json` 继续作为成员资料的权威来源；新增字段必须可选。
- 现有 SQLite 统计记录原样保留，不覆盖、不重算。
- JavaScript 加载失败时，成员列表、排行和加入说明仍可使用。
- 所有数据库变更使用向前迁移；发布前备份数据库并保留可回滚镜像。

## 5. 信息架构与首页体验

### 5.1 顶部导航

保留现有 Logo、无聊湾名称、昼夜切换、排行榜和“一起无聊”。移动端将操作收纳为紧凑菜单，但不改变入口语义。

### 5.2 首页顺序

1. 品牌区与简短说明。
2. 三个轻入口：`随便逛逛`、`今日航线`、`最新漂流瓶`。
3. 现有“今日无聊”成员列表。
4. 30 天排行摘要。
5. 状态观察摘要。
6. QQ 群、Badge、品牌语录和构建版本。

新增模块不能遮盖成员列表。首屏在移动端至少能看到品牌、一个探索按钮和部分成员内容。

### 5.3 成员卡

保留头像、名称、描述、GitHub、UV、RV 和等级。V2 可增加：

- 可选主题标签；
- 本地“已访问”邮戳；
- 可选最新文章提示；
- 收藏按钮（仅本地存储）；
- 对键盘、触屏和 `prefers-reduced-motion` 友好的轻动效。

成员卡的主点击仍前往成员博客，不增加中间跳转页。

### 5.4 湾内动态

现有 WebSocket 实时通知保留，但从抢占注意力的 Sticky Alert 调整为可折叠的“湾内动态”。动态默认只显示国家/地区和站点，不显示经过遮罩的 IP 片段。用户可暂停动态与动效。

## 6. 排行榜设计

### 6.1 数据定义

- `UV`：现有 Badge 访问去重计数。
- `RV`：从成员域名进入无聊湾的去重计数。
- `最后活动`：`max(updated_at, latest_referrer_at)`。

探索路线、收藏、护照和分享行为使用独立事件，不写入 UV/RV。

### 6.2 榜单

1. **30 天活跃榜（首页默认）**  
   统计最近 30 个自然日。排序值为 `UV + RV`，同分时依次比较 RV、UV、最后活动。页面同时展示原始 UV、RV、窗口和公式。

2. **上升榜**  
   比较最近 7 天与此前 7 天的 `UV + RV`。最近 7 天总量少于 5 的站点不进入正式排序，避免极小样本占据榜首。增长率定义为 `(最近 7 天总量 - 此前 7 天总量) / max(此前 7 天总量, 5)`；先按增长率排序，再按绝对增量排序。增长率在界面中封顶显示为 `500%+`，防止异常值主导视觉。

3. **经典总榜**  
   保留现有历史排行语义和原始 UV/RV 数据。为保持链接语义，`/rank` 默认仍显示经典总榜；用户可在同页切换到 30 天活跃榜和上升榜。

### 6.3 公平性

- 排名公式公开。
- 新功能产生的点击不计入 UV/RV。
- 去重窗口继续存在，但去重键不再包含明文 IP。
- 对单一站点的异常流量只标记并进入人工审查，不在首版自动处罚。
- 首页的“随便逛逛”和每日航线不直接按照榜单排序，避免强者恒强。

## 7. 成员状态与移除候选

“即将移除”更名为“状态观察”，保留功能目的但降低误判和惩罚感。

### 7.1 状态

- **活跃：** 最近活动少于 30 天，或站点检测正常且存在近期互动。
- **安静：** 30 天以上无活动，但站点可访问；只提示，不进入移除候选。
- **观察：** 60 天以上无活动，并且连续 3 次每日站点检测失败，或人工确认 Badge 已移除。
- **可移除候选：** 90 天以上无活动，并且连续 7 次每日检测失败，或 Badge 已连续 30 天确认缺失。

### 7.2 规则

- 不自动删除成员。
- 任何移除都必须由维护者人工确认并通过正常 PR 完成。
- 页面展示状态原因、最后活动、最近检测、宽限期和更新资料入口。
- Feed 失败、未提供 Feed 或内容长期不更新，不影响成员资格。
- 站点健康检测只访问公开首页，遵守短超时、低频率和固定 User-Agent。

## 8. 探索、趣味与传播

### 8.1 今日航线

- 每个上海时区自然日生成一条由 5 个可用成员组成的路线。
- 路线在首次生成后写入 `daily_routes`，保证当天所有用户看到同一路线。
- 选择时覆盖尽可能多的主题，并提高近期曝光较少、新加入且状态正常成员的权重。
- 隐藏、观察和可移除候选成员不进入自动路线。
- 路线完成状态仅存储在浏览器本地，不影响排行。

### 8.2 随便逛逛

- 从状态正常的成员中公平随机选择下一站。
- 浏览器优先排除本地已访问成员；当候选耗尽后提示用户重置。
- 用户可按主题筛选，但首版不做复杂个性化推荐。

### 8.3 无聊护照

本地存储键为 `boringbay.passport.v1`，保存访问成员 ID、收藏、每日航线完成状态、连续探索天数和成就。数据不上传服务器。

首版成就包括：首次出湾、五岛巡游、深夜旅人、冷门打捞员和连续三日。成就只用于娱乐，不授予排行优势。

界面明确提示：清除浏览器数据会丢失护照。首版不提供账号同步；可选的导出/导入不进入首期范围。

### 8.4 最新漂流瓶

成员可在 `membership.json` 增加可选 `feed_url`。后台定时获取 Feed，并缓存：

- 标题；
- 原文 URL；
- 纯文本短摘要；
- 发布时间；
- 成员 ID；
- 最近成功抓取时间。

不存储完整正文。点击直接打开原博客。Feed 失败时保留旧缓存并标记陈旧；超过 7 天未成功更新时停止在“最新”区域展示，但不影响成员卡。

### 8.5 分享

- 每日航线拥有稳定 URL，例如 `/route/2026-09-16`。
- 服务端提供带 Open Graph 元数据的路线页面和品牌分享图。
- 完成卡可在浏览器端生成，包含日期、路线主题和邮戳数量，不包含浏览历史或个人标识。
- 完成数量可被用户修改，因此只作为娱乐信息，不能进入正式统计或奖励。
- 新款动态 Badge 是可选接口；旧接口和嵌入代码继续有效。

## 9. 技术架构

### 9.1 继续使用的技术

- Rust + Axum；
- Askama 服务端模板；
- Diesel + SQLite；
- 原生 JavaScript；
- 现有 amd64/arm64 构建与 GHCR 发布链路。

依赖升级独立成基础 PR，不与大功能一次性混合。

### 9.2 模块边界

- `members`：加载、验证和查询成员资料；
- `statistics`：现有 UV/RV 写入和聚合；
- `ranking`：榜单窗口、分数与状态规则；
- `discovery`：每日航线与公平随机；
- `feed`：Feed 安全获取、解析、清洗和缓存；
- `site_health`：低频站点检测与状态汇总；
- `share`：路线页面和分享图；
- `web`：路由、模板 ViewModel 与错误映射。

模块通过明确的数据结构通信；Feed 或健康模块失败不能阻止核心页面渲染。

### 9.3 数据表

现有 `statistics` 表保留。新增表：

- `daily_routes(date, member_ids, generated_at)`；
- `feed_items(member_id, url, title, summary, published_at, fetched_at)`；
- `feed_sources(member_id, last_success_at, last_error_at, error_kind)`；
- `site_health(member_id, checked_at, reachable, status_code, badge_state)`；
- `product_events(day, event_kind, member_id, count)`，只保存日级聚合计数。

所有表增加满足窗口查询的索引。SQLite 启用 WAL，后台任务使用短事务并在忙锁时有限重试。

### 9.4 后台任务

- 现有统计每 5 分钟落盘继续保留；
- Feed 默认每 30 分钟刷新，单源最短间隔 30 分钟；
- 站点健康每天一次；
- 每日航线按需生成并持久化；
- 单实例部署下在进程内调度，多实例部署前必须增加数据库租约锁。

## 10. 隐私与安全

### 10.1 访问统计

- 不在日志中记录完整 IP。
- 去重键使用带轮换盐的 HMAC，并只保存在短期内存缓存；不落库。
- 缺少 Cloudflare 请求头时安全降级，不 `unwrap()`，也不信任任意客户端伪造的转发头。
- WebSocket 不发送 IP 片段，只发送粗粒度国家/地区与成员信息。

### 10.2 Feed SSRF 防护

- 只允许 HTTPS。
- DNS 解析后拒绝回环、私网、链路本地、保留地址和 Unix socket。
- 每次重定向重新验证目标；最多 2 次重定向。
- 连接超时 3 秒，总超时 8 秒，响应上限 1 MiB。
- 只接受预期 XML 内容；解析器禁用外部实体。
- 摘要去除 HTML、脚本、样式和不可见控制字符，并在模板层再次转义。

### 10.3 供应链

- 第三方 GitHub Actions 固定到审核过的提交 SHA。
- Docker 基础镜像固定到明确版本和摘要，定期升级。
- CI 执行依赖审计、测试和格式检查；审计告警需人工判定，不能静默忽略。

## 11. 错误处理与降级

- 单个 Feed 失败：保留旧缓存，隐藏过期内容，成员卡正常。
- 健康检测失败：记录失败，不立即改变成员资格。
- 分享图失败：路线页面仍可打开，回退到默认 Open Graph 图片。
- WebSocket 失败：页面正常，客户端指数退避重连并允许用户关闭。
- 数据库忙：短事务有限重试；超过上限记录结构化错误并跳过该周期。
- 本地存储不可用：护照与收藏隐藏，其余体验不受影响。
- 无 Cloudflare 头：请求仍可响应，但不计入需要可信来源信息的统计。

## 12. 测试策略

### 12.1 单元测试

- 30 天榜、上升榜和经典榜排序；
- 最后活动与状态观察边界（30/60/90 天）；
- 每日航线稳定性、去重、主题覆盖和候选过滤；
- Feed URL 安全校验、重定向与大小限制；
- Feed 解析、摘要清洗和陈旧缓存；
- IP 去重键不包含明文 IP。

### 12.2 集成测试

- 旧页面与旧 API 的响应兼容；
- 数据库从现有版本迁移到 V2；
- Feed/健康任务失败时首页可用；
- Askama 模板关键快照；
- 无 JavaScript 时成员列表、排行和加入说明可用。

### 12.3 发布验收

- amd64 与 arm64 CI 全绿；
- 旧 Badge 嵌入测试通过；
- 现有统计数据行数和关键聚合值迁移前后相等；
- 首页、排行、加入页和分享路线通过移动端与桌面端检查；
- 数据库备份恢复演练通过；
- 功能开关可关闭 V2，而无需回滚数据库。

## 13. 指标

只记录日级聚合事件，不建立用户画像：

- 今日航线开始和完成次数；
- 随便逛逛使用次数；
- 成员站点出站点击；
- 漂流瓶原文点击；
- 分享按钮与分享链接打开次数；
- 加入说明访问和 GitHub 编辑入口点击；
- 由本地护照判断并只上报布尔事件的“再次到访”，服务器不接收稳定用户 ID。

首期成功条件：V2 上线后连续四周，成员出站点击、回访代理指标（重复日访问的匿名聚合）和加入入口点击均较 V1 基线提升，且 Badge/API 错误率不高于基线。

## 14. 风险登记表

### R1. 产品身份被新功能稀释（中概率 / 高影响）

**风险：** 探险、护照和 Feed 抢走成员列表与原设计的中心位置。  
**控制：** 新入口轻量化；“今日无聊”仍是首页主体；保留品牌色、无聊脸、原文案和原页脚。  
**验收：** V2 截图评审必须能在首屏识别无聊湾，并在一次滚动内到达成员列表。

### R2. 排行规则引发成员争议或刷量（中概率 / 高影响）

**风险：** 新公式改变名次，或探索功能被用来刷榜。  
**控制：** 经典榜永久保留；公式公开；探索/分享事件与 UV/RV 分表；异常只标记、人工复核。  
**残余风险：** 无账号和强身份验证时无法完全阻止分布式刷量，首版不承诺反作弊绝对准确。

### R3. 状态观察误伤正常成员（中概率 / 高影响）

**风险：** 临时宕机、低流量或移除 Badge 被错误理解。  
**控制：** 同时使用最后链入与最后受访；多次检测；30/60/90 天宽限；绝不自动删除；展示原因并允许更新。  
**验收：** 边界条件单元测试和人工候选清单复核通过。

### R4. RSS 抓取造成 SSRF、资源耗尽或版权争议（中概率 / 高影响）

**风险：** 恶意 Feed 地址访问内网，超大响应拖垮服务，或过度转载内容。  
**控制：** 明确 opt-in；公网 HTTPS 校验；重定向复验；超时和大小限制；禁用外部实体；仅保存标题、短摘要和原文链接。  
**残余风险：** DNS 重绑定和异常解析器输入需要专门安全测试。

### R5. IP 隐私与可信代理处理错误（中概率 / 高影响）

**风险：** 当前日志记录完整 IP，且直接依赖 Cloudflare 头。  
**控制：** 删除明文日志；短期 HMAC 去重；只在确认请求来自可信代理时使用 Cloudflare 头；WebSocket 不发送 IP。  
**验收：** 日志和实时消息中搜索不到完整 IP，伪造头测试不计数。

### R6. 老依赖升级导致兼容性回归（高概率 / 中高影响）

**风险：** Axum 0.4、Askama 0.11、Diesel 2.0 RC 与当前代码年代较老，一次升级可能同时影响路由、模板和迁移。  
**控制：** 依赖升级独立 PR；先补兼容测试；按框架逐步升级；不把升级和产品功能混在同一提交。  
**残余风险：** 升级可能需要较大 API 适配，应允许暂时保留部分旧版本。

### R7. SQLite 写锁与后台任务竞争（中概率 / 中影响）

**风险：** 统计落盘、Feed 和健康任务增加写竞争。  
**控制：** WAL、索引、短事务、批量写入、有限忙锁重试、任务错峰。  
**升级触发：** 若持续出现写锁超时或单库体积/请求量超过实测容量，再评估 PostgreSQL；V2 不提前迁移。

### R8. 本地护照丢失或跨设备不一致（高概率 / 低中影响）

**风险：** 用户清理浏览器后进度丢失。  
**控制：** 明确说明本地存储属性；成就不绑定权益；首版不伪装成云同步。  
**残余风险：** 部分用户仍会失望，但建设账号系统的成本与当前目标不匹配。

### R9. 分享卡被伪造或用于垃圾传播（中概率 / 低中影响）

**风险：** 无登录条件下完成数量不可验证。  
**控制：** 分享卡只表达娱乐性结果，不授予排行、身份或奖励；路线 URL 固定且不接受自由文本。  
**验收：** 分享接口不能注入 HTML、脚本或任意外链。

### R10. 动效、地图和颜色影响可访问性（中概率 / 中影响）

**控制：** 键盘可操作、可见焦点、语义 HTML、对比度检查、`prefers-reduced-motion`、无 JS 降级。  
**验收：** 关键流程通过键盘和移动端检查。

### R11. GitHub Actions 与镜像供应链风险（中概率 / 高影响）

**风险：** 当前部分第三方 Action 跟随可变 `main` 标签，基础镜像也未固定。  
**控制：** 固定 Action SHA 和基础镜像摘要，减少默认 Token 权限，为发布任务设置明确权限。  
**验收：** CI 配置中不存在未经批准的可变第三方引用。

### R12. 范围膨胀导致长期无法发布（高概率 / 高影响）

**控制：** 四阶段独立 PR，每阶段都可上线；首版不做账号、评论、社交关系、全文搜索和复杂推荐。  
**验收：** 每个阶段拥有独立验收标准和功能开关，后续阶段不能阻塞前一阶段发布。

## 15. 分阶段交付

### 阶段 1：安全和可测试基础

- 兼容测试、模板快照和迁移测试；
- Cloudflare 头安全处理与 IP 隐私；
- 固定 Actions 和基础镜像；
- 模块边界初步拆分；
- 依赖升级单独评估。

### 阶段 2：排行榜与状态观察

- 最后活动修正；
- 30 天活跃榜、上升榜和经典榜；
- 站点健康表与每日检测；
- 状态观察页面和人工候选流程。

### 阶段 3：探索与护照

- 首页现代化但保留结构；
- 今日航线、随便逛逛、主题标签；
- 本地护照、收藏和成就；
- 湾内动态降噪与隐私调整。

### 阶段 4：Feed 与分享

- opt-in Feed 字段、抓取器和缓存；
- 最新漂流瓶；
- 路线分享页面、Open Graph 图片和本地完成卡；
- 可选新版 Badge。

## 16. 最终验收原则

V2 完成时必须同时满足：

1. 旧功能、旧 URL、旧 Badge 和历史数据没有丢失。
2. 无登录用户能完成探索、护照和分享流程。
3. 新功能失败时核心站点仍可用。
4. 排行和状态观察规则公开且有测试。
5. 不在日志、数据库或 WebSocket 中暴露完整 IP。
6. 每个阶段可独立回滚或通过功能开关关闭。
